# 主框架边界

## 所有权

| 所有者 | 负责 |
| --- | --- |
| Shell 桌面主程序 | 环境定位、唯一内核、原生窗口、真实账户、应用中心与关闭协调 |
| @cxx/host-runtime | 存储、安装与运行环境端口、应用会话、可信模块登记、受控加载与释放 |
| @cxx/app-shell | Vue/DOM 外壳、窗口栏、账户工作区、设置与日志展示；不查询业务资料 |
| @cxx/ui / @cxx/icons | 通用控件、交互、主题与图标 |
| 子应用 | 业务服务、业务资料、独立安全桥与页面，以及自身后台进程 |

两个框架包在本仓维护，名称和公开入口继续有效。UI 仓只维护通用 UI、图标与可选项目套件，文档和示例通过归档消费外壳。RepoDock 不再维护宿主包，正常启动只登记自身模块并激活独立 Shell。

## 可信加载

应用目录通过公开清单描述 id、版本、工厂、preload 和可选 runtimePackages。加入只检查元数据与摘要，不执行代码；打开时根据宿主可信视图身份重新核验资格和摘要，再调用工厂。更新需要核对令牌，文件再次变化则拒绝确认。外部声明不能将自己标成基础设施以绕过资格。

中央产品编码由可信安装目录 package.json.cxxApplication.productCode 明确提供，与包名及内部应用 ID 独立。源·派生的声明为 cxx-repodock，部署流为 deploy-flow；产品声明是唯一映射来源，宿主不维护软件特例表。未声明的旧产品保留原应用 ID 契约。上一版无 productCodeSource 的推断登记在唯一读取适配层补齐正确编码，不回写资料或改变 ID；新登记及更新核对将编码与入口摘要一起绑定。Renderer 与外部登记参数不能覆盖产品编码或基础设施资格。

软件可在 package.json.cxxApplication.icon 声明目录内 PNG；旧产品兼容 build/<包名>-icon.png 约定。图标受根目录、PNG 签名和大小约束，缺失时使用 Shell 回退。菜单的有界数据 URL 和子窗口本地路径来自同一资源。Shell 使用已安装 @cxx/icons 的 38-workspace，构建时由现有浏览器工具生成窗口 PNG，不新增手绘副本。开发、打包均调用同一窗口装配入口。

工厂返回 load(view) 和 dispose()。关闭会取消初始化并等待业务与运行环境释放；只有该应用拥有的模块缓存可被清理，其他活动应用共享的模块保持有效。产品通过 host 端口消费主框架，不创建第二套窗口或账户内核。Renderer 仅调用安全桥，主框架根据实际 webContents 检查主体。

框架的主程序只装配真实账户提供者。合成账户仅在 tests/helpers 的隔离夹具中注入，不是产品启动参数，也不进入 EXE。

## 环境与资料

正式环境由当前系统账户定位文件和环境记录确定。安装路径、代码分支和盘符不决定资料位置。显式 --test-root 使用独立环境，默认启动不访问测试根。

旧应用中心继续使用同一登记文件，保留停用、安装位置和分组。浏览器资料保留原登记位置。旧产品到公开子应用的转换只登记原安装位置，不搬动项目资料。

生产安装需要发布者认证元数据。内部测试目录包必须指定测试根目录，不借测试模式免除登录或订阅。卸载默认保留共享资料，应用中心移除只解除登记。

## 验证

框架单元和原生测试、三主题浏览器行为、独立 tarball 及 TypeScript 消费分别验证边界。产品使用各自的正式测试入口；运行目录被用户实例占用时，从已提交 SHA 建立隔离 Git 检出安装并验证。隔离检出不是第二份开发源码。

## 软件切换

应用目录对所有已登记软件提供 installed、configuredEnabled 与有效 enabled 状态，产品按同一快照构建切换菜单。业务打开前保留原活动页面；主框架只在准备成功且仍是最后一次选择时激活目标，迟到结果不能夺回焦点。重复打开共用一份加载任务，原生视图保持同一会话。

DOM 外壳的跨软件入口在异步回调期间复用公共 UI 左右骨架，菜单与窗口栏继续可用，原业务节点保留。失败或返回原软件后恢复原节点；关闭外壳使迟到结果失效。软件的加载与资格仍由可信宿主核对。

## 默认窗口归属

桌面 application-opening 是菜单、启动参数及公共内核激活的唯一打开策略。首次打开创建主窗口，后续软件默认复用该窗口；未指定软件的重复启动保留当前活动软件。显式拆窗仍由应用会话负责，重新激活已拆开的软件只聚焦其现有窗口。打开失败保留原页，窗口标题和图标跟随活动应用及关闭后的回退视图。

## 应用菜单归属

安装声明的 navigation 仅包含该应用二级入口，主框架应用目录持有一级安装顺序。DOM 外壳通过 setApplicationMenu 消费完整目录，不以当前应用重排菜单。跨应用功能带 entryId 由主进程验证，目标入口与修订号同时通过激活通知和 metadata.navigation 提供，冷启动不依赖事件订阅时序。应用中心只负责安装管理，不作为业务菜单项插入。
